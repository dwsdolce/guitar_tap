# Export checker

One judge for the spectrum images (PNG) and PDF reports of all three editions. Each edition's export tests drive
the real app — import a fixture, export from the main window and from Saved Measurements — and lay the files out
as `<folder>/<case>/<main|saved>/<file>`; `check_exports.py` measures the parts of each file and compares them
with Swift's, within tolerances. It compares parts, not pixels, so fonts and off-screen drawing that differ by
operating system do not fail it, while a moved, missing or resized part does.

## What it measures

- **PNG** — the image size; the header title and its rows; the chart title; the plot's edges; the frequency labels,
  each centred on its grid line and none reaching past the plot's edge; the x-axis title; the summary below the chart
  (detected peaks, or a material's properties); the legend and its number of entries.
- **PDF** — every text line's baseline, text and typography (its runs of weight and colour), per page — dates
  compared as they are, only the "Generated by" footer, versions and the platform set aside, ligatures read as
  letters; each page's image rectangles.
- **Names** — each file's name: a measurement's exports are named with its own timestamp.

The drivers run the apps in UTC, so a measurement's date prints the same on every machine.

## Files

| File | What it is |
|---|---|
| `check_exports.py` | the checker |
| `expected.json` | Swift's measurements of its own exports, and the tolerances — regenerate with `mint` |
| `tolerances.json` | the tolerances, in points, copied into `expected.json` when it is minted |
| `requirements.txt` | NumPy, Pillow, pdfminer.six, pinned — included by each edition's `requirements-dev.txt` |
| `sync.sh` | hub only: copy the checker into the editions, or `--check` that their copies match |

The hub holds the source of truth. Each edition holds a byte-identical copy (`Tooling/export-check/` in Swift and
Python, `tooling/export-check/` on the web) and runs it without the hub.

## Running

Each edition runs the checker with its own `.venv`, set up from its `requirements-dev.txt` (which includes this
`requirements.txt`) — from the edition's root:

    python3.14 -m venv .venv
    .venv/bin/pip install -r requirements-dev.txt

    .venv/bin/python <export-check>/check_exports.py check <folder>   # judge an edition's exports against expected.json
    .venv/bin/python <export-check>/check_exports.py show <file>      # one file's measurements

Each edition's runner produces the folder and runs the check:

- Swift — `Tooling/run-export-uitests.sh` (the XCUITest export tests; they take over the mouse and keyboard).
- Python — `Tooling/run-export-check.sh` (the `pytest-qt` export tests).
- Web — `npm run test:exports` (the Playwright export tests).

## When Swift's exports change on purpose

Run Swift's export tests, then from the hub (its `.venv`, set up from its `requirements-dev.txt`):

    .venv/bin/python tooling/export-check/check_exports.py mint <swift-folder>
    tooling/export-check/sync.sh

and commit the new `expected.json` in the hub and in each edition.
